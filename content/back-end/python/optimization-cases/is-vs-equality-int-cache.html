Python 優化案例：用 is 比較數值（小整數快取陷阱）

is 有時對、有時錯 · 結論：比較「值」一律用 ==；is 只用在 None 這類單例

原因

用 is 比較數字 / 字串→is 比的是「是不是同一個物件」→小整數、部分字串剛好被重複使用→測試時看起來對，換個值就錯

原本的寫法：

LIMIT = 1000

def over_limit(total):
    return total is LIMIT       # 想比「值」，卻用了 is

print(over_limit(1000))         # True：同一個檔案裡的常數 1000 剛好是同一個物件
print(over_limit(int("1000")))  # False：值一樣，但是在執行時新建的物件

a = 256
b = int("256")
print(a is b)                   # True：-5～256 有快取，讓人誤以為 is 可以比數字
  1. is 比的是身分（identity）：兩個名字是不是指向同一個物件，不是值相不相等。
  2. CPython 會重複使用某些物件：-5～256 的小整數、看起來像識別字的短字串、同一段程式碼裡相同的常數。這些情況 is 剛好回傳 True。
  3. 這些都是實作細節，不是語言保證；值一來自輸入、計算、網路，就會是新物件，is 就變成 False。

名詞 先看懂這幾個詞

身分（identity）與 id()
每個物件都有唯一的身分，可以用 id(x) 看到。a is b 等於 id(a) == id(b)。比喻：兩張鈔票面額一樣（==），但序號不同（is 為 False）。
值相等（==）與 __eq__
a == b 會呼叫 a.__eq__(b)，由型別決定「怎樣算相等」：數字比數值、字串比內容、list 逐項比較。
小整數快取（small int cache）
CPython 啟動時就先建好 -5～256 的整數物件，之後用到這些值都拿同一個物件，所以它們的 is 會是 True。257 以上每次運算都可能產生新物件。
字串駐留（string interning）
CPython 會讓某些字串（例如程式碼中像變數名稱的字串常數）共用同一個物件，以節省記憶體、加速字典查找。執行時組出來的字串通常不會被駐留： 
s1 = "hello"
s2 = "".join(["hel", "lo"])
print(s1 == s2)  # True：內容一樣
print(s1 is s2)  # False：是另一個物件
常數合併（constant folding / 共用常數）
同一個程式碼區塊（一個 .py 檔、一個函式）被一次編譯時，相同的常數只會建立一份。所以同一個檔案裡 x = 257、y = 257 通常會指向同一個物件。
單例（singleton）
整個程式只會有一個的物件：None、True、False、NotImplemented、...（Ellipsis）。因為只有一個，用 is 比才有意義，也最快。

解法 比值用 ==，比 None 用 is

LIMIT = 1000

def over_limit(total):
    return total == LIMIT       # 比值：不管物件從哪裡來都正確

print(over_limit(int("1000")))  # True

def find(items, target=None):
    if target is None:           # None 是單例：用 is，也不會被自訂 __eq__ 影響
        return []
    return [x for x in items if x == target]

需要「確實是同一個物件」時才用 is，例如自訂的哨兵值：

_MISSING = object()                 # 獨一無二的物件，當作「沒傳參數」的記號

def get(d, key, default=_MISSING):
    if key in d:
        return d[key]
    if default is _MISSING:          # 這裡要的就是「是不是那個物件」
        raise KeyError(key)
    return default

判斷

要比較的東西用
數字、字串、list、dict、自訂物件的「內容」==
Noneis None / is not None（PEP 8 建議）
自訂哨兵物件、確認兩個名字指向同一個物件is
True / False直接寫 if flag:；不要寫 == True，也不必 is True（除非要排除 1 這類「真值」）
x is 257、name is "admin" 這種和字面值比不要：Python 3.8+ 會發出 SyntaxWarning

取捨 注意

  • == 會呼叫 __eq__，可能被自訂型別改寫（例如 NumPy 陣列的 == 回傳陣列而不是 bool），這也是 None 檢查要用 is 的原因。
  • is 比 == 快一點點，但不能為了速度用 is 比值，結果不正確再快也沒用。
  • 快取範圍與駐留規則是 CPython 的實作細節，不同版本、不同直譯器（PyPy）都可能不同，不要寫依賴它的程式。
更正原筆記：
  • 原筆記說 x = 257; y = 257; x is y 會輸出 False。這只在互動式 REPL 分兩行輸入時成立（每行各自編譯，產生兩個物件）。寫在同一個 .py 檔裡執行，常數通常會被合併成同一個物件，結果是 True。兩種結果都可能出現，正好說明不該用 is 比數字。
  • 原筆記沒提到：Python 3.8 起，is / is not 直接和字面值（數字、字串）比較時，會發出 SyntaxWarning: "is" with a literal. Did you mean "=="?。
  • 「短字串會被快取」不精確：駐留的是像識別字的字串常數等特定情況，不是單看長度；執行時產生的字串通常不會駐留。
