Go 編譯器利用 **多核心平行編譯**、**快取依賴**、**簡潔語法**

---

## 1. 多核心平行編譯 (Parallel Compilation)

* **Go 編譯器設計為並行處理多個 package**。
  Go 程式碼通常會分成多個 package（模組），編譯時會同時對多個 package 執行編譯任務，而不是一個接一個串行編譯。

* **利用多核 CPU，並行編譯不同 package**，提升 CPU 利用率。
  例如，若你有 8 核 CPU，`go build` 預設會同時執行最多 8 個編譯工作（`-p` 預設 = GOMAXPROCS，通常等於 CPU 核心數），大幅縮短整體編譯時間。

* 這在大型專案中特別明顯，因為很多 package 可以獨立編譯。

* Go 的命令工具 `go build` 會自動控制並行度，若要調整可同時執行的編譯工作數，應使用 `go build -p N` 明確指定。`GOMAXPROCS` 本身是 Go **runtime** 的設定（限制程式執行時可同時執行 Go 程式碼的 OS 執行緒數），不是 `go build` 的平行度參數；只是 `-p` 的預設值剛好取自 `go` 指令本身的 `GOMAXPROCS`（通常等於 CPU 核心數），所以設定這個環境變數只會「間接」影響預設值。

---

## 2. 快取依賴 (Dependency Caching)

Go 有兩種不同的快取，容易混淆：

* **Module 快取（module cache）**：Go 使用 **module** 來管理第三方套件依賴，下載過的 module **原始碼**存在 `GOMODCACHE`（預設 `$GOPATH/pkg/mod`）。
  已下載的版本不需要每次都重新下載，節省的是網路與 I/O。

* **建置快取（build cache）**：真正讓「重複編譯變快」的是 `GOCACHE`（可用 `go env GOCACHE` 查看，例如 macOS 為 `~/Library/Caches/go-build`）。
  Go 會依原始碼、編譯參數等內容計算雜湊，**已編譯過且沒有變動的 package 直接重用快取的編譯結果**，不必重新編譯。

* Go 編譯器利用這兩層快取，避免重複下載與重複編譯，節省了 I/O 和 CPU 時間。

---

## 3. 簡潔語法（Language Simplicity）

* Go 沒有複雜的繼承、多態、巨集、模板元編程等特性。

* 語法結構單純，語言規範簡明，讓編譯器**語法分析（parsing）和語意分析（semantic analysis）階段非常快速且低複雜度**。

* 這不僅使編譯器容易優化，也縮短了每次編譯所需的 CPU 時間。

* 省去複雜語法結構的編譯負擔，編譯器可以專注在直接生成高效機器碼。

---

## 總結

| 技術點     | 如何提升編譯速度                       |
| ------- | ------------------------------ |
| 多核心平行編譯 | 同時編譯多個 package，提高 CPU 使用效率     |
| 依賴快取    | module 快取避免重複下載；build 快取（`GOCACHE`）重用未變動 package 的編譯結果 |
| 簡潔語法    | 降低編譯器語法和語意分析複雜度，編譯步驟更快         |
