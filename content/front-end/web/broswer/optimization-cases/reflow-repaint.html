瀏覽器優化案例：Reflow 與 Repaint

改樣式、讀版面造成頻繁重算 · 結論：讀寫分批、動畫用 transform + rAF

原因

JS 改樣式 / 讀版面屬性→瀏覽器重新計算版面（Reflow）→再重新繪製（Repaint）→頻繁發生 → 掉幀、卡頓
// 常見的壞寫法：讀、寫交錯（layout thrashing）
for (const el of items) {
  const w = el.offsetWidth          // 讀：為了給正確答案，瀏覽器必須「立刻」重算版面
  el.style.width = w + 10 + 'px'    // 寫：讓版面失效
}                                    // 下一圈的讀又要重算一次 → 每圈都 Reflow
  1. Reflow（回流）：改變大小 / 位置 / 新增刪除 DOM，瀏覽器要重新計算元素的幾何，且可能連鎖影響整個頁面。
  2. Repaint（重繪）：只改外觀（顏色、陰影），不重算版面但要重畫，較輕。
  3. 真正拖慢的常是「寫了樣式之後馬上讀版面屬性」：強迫瀏覽器同步重算版面，而且在迴圈裡重複發生。
更正原筆記：「連續設定三個 style 屬性會觸發三次 Reflow」不精確。瀏覽器會把連續的樣式寫入合併，等到需要時才算一次；真正的問題是寫完又馬上讀（讀 offsetWidth、offsetHeight、getComputedStyle 等）造成「強制同步 Reflow」。改用 cssText 只是寫法整齊，並不是主要的效能差異。

名詞 先看懂這幾個詞

渲染流程
樣式計算 → 版面（Layout / Reflow） → 繪製（Paint / Repaint） → 合成（Composite，GPU 把圖層組起來）。越前面的步驟被觸發，後面也都要重做，成本越高。
強制同步 Reflow（layout thrashing）
寫入樣式後立刻讀取版面屬性，瀏覽器為了給出正確的值，必須提前把版面算完。在迴圈裡「讀、寫、讀、寫」就會反覆發生。
transform / opacity
這兩個屬性通常只在「合成」階段處理（交給 GPU），不觸發 Reflow、多半也不觸發 Repaint，所以最適合做動畫。
requestAnimationFrame（rAF）
請瀏覽器「在下一次繪製前」執行你的函式，頻率與螢幕更新同步（通常 60 次 / 秒），比 setTimeout(16) 準確、不會多做看不到的更新。

解法

① 先全部讀、再全部寫

const widths = items.map((el) => el.offsetWidth)           // 讀：一次做完（只重算一次版面）
items.forEach((el, i) => el.style.width = widths[i] + 10 + 'px')   // 寫：一次做完

② 改 class 而不是逐個改 style；批量建立用 DocumentFragment

el.classList.add('active')                      // 樣式寫在 CSS，一次切換

const frag = document.createDocumentFragment()  // 先在記憶體裡組好
for (let i = 0; i < 100; i++) {
  const div = document.createElement('div')
  div.textContent = `Item ${i}`
  frag.appendChild(div)
}
document.body.appendChild(frag)                 // 一次放進 DOM，只重算一次

③ 動畫用 transform + requestAnimationFrame

// 壞：改 left 會觸發 Reflow，setTimeout 也不跟螢幕同步
function move() { el.style.left = ++i + 'px'; setTimeout(move, 16) }

// 好：transform 不觸發 Reflow，rAF 與螢幕更新同步
function move() { el.style.transform = `translateX(${++i}px)`; requestAnimationFrame(move) }
requestAnimationFrame(move)

判斷 哪些屬性觸發什麼

改這些觸發成本
width / height / margin / padding / top / left / position、增刪 DOMReflow + Repaint高
color / background-color / box-shadow / visibilityRepaint中
transform / opacity（通常）只合成低（最佳）
  • 隱藏元素：visibility: hidden 只 Repaint（但仍佔空間）；display: none 會 Reflow（元素離開版面）。看是否需要保留位置選擇。
  • will-change: transform 可提示瀏覽器預先建立圖層，但不要濫用（每個圖層都吃記憶體）。
