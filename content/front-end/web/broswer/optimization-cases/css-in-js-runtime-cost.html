CSS 優化案例：CSS-in-JS 的執行期成本（styled-components）

動態樣式多的元件更新變慢、SSR 首屏先出現沒樣式的畫面 · 結論：常變的值不要寫進樣式規則；SSR 一定要把樣式跟 HTML 一起送出；能在建置時決定的樣式就別留到執行期

原因

元件渲染→執行樣式裡的插值函式→組出 CSS 字串、算 hash→新組合 → 插入新 CSS 規則→瀏覽器重算樣式
const Box = styled.div`
  padding: 16px;                                         // 靜態：只處理一次
  transform: translate(${p => p.x}px, ${p => p.y}px);    // 每組不同的 x / y = 一個新 class + 一條新規則
`

// 拖曳時每一幀 x / y 都不同
<Box x={pos.x} y={pos.y} />
  1. styled-components 在執行期產生 CSS：每次渲染要執行插值函式、組字串、算 hash；遇到沒看過的樣式組合就要把新規則插入 <style>，瀏覽器跟著重算樣式。
  2. 把高頻變動的值（座標、捲動位置、進度）寫進樣式，每個值都產生一個新 class，規則只會越來越多（開發模式會出現「Over 200 classes were generated」警告）。
  3. SSR 沒有收集樣式時，伺服器送出的 HTML 不含 CSS，要等 JS 下載、執行後才注入 → 先看到無樣式畫面（FOUC）。
  4. 函式庫本身與產生樣式的程式都要在客戶端下載、執行，增加 JS 成本。
更正原筆記：
  1. 原筆記說「每次渲染都會解析模板字串、生成 class、注入 CSS」—— 不精確。模板的靜態部分在定義時就處理好；每次渲染只重新執行有插值函式的部分，結果和之前一樣就沿用已有的 class，只有出現新組合時才注入新規則。完全靜態的元件成本很低。
  2. 原筆記的 FOUC 說明（「首次繪製較快但注入較慢」）含糊。正確說法：沒有設定 SSR 樣式收集（ServerStyleSheet / registry）時，HTML 先到、樣式等 JS 執行後才注入，所以會先畫出沒樣式的內容再跳成有樣式。設定正確就不會發生。
  3. 原筆記說 babel-plugin-styled-components「在建置時預處理樣式」：它主要提供SSR 兩邊一致的 class 名稱、方便除錯的 displayName、壓縮與轉譯模板；不會把 CSS 抽成靜態檔，執行期產生樣式的成本仍在。
  4. 原筆記的「約 12–13kb gzipped」未註明版本與來源，大小依版本而異，請以實際打包分析為準。

名詞 先看懂這幾個詞

CSS-in-JS
把 CSS 寫在 JS 檔裡，跟元件放在一起。styled-components、Emotion 屬於執行期（runtime）型：瀏覽器跑 JS 時才產生 CSS。vanilla-extract、Linaria 等屬於零執行期（zero-runtime）型：建置時就輸出成一般 .css 檔。
模板字串插值 ${p => ...}
styled.div`...` 是 tagged template literal。${p => p.color} 是一個函式，元件每次渲染時被呼叫、收到 props，回傳的值會被組進 CSS。插值越多、變化越頻繁，執行期工作越多。
FOUC（Flash of Unstyled Content）
瀏覽器先把 HTML 畫出來，但樣式還沒到，使用者看到一瞬間「沒排版的原始內容」，接著樣式套上去又跳一次。
ServerStyleSheet / Style registry
SSR 時用來收集這次渲染用到的所有樣式，輸出成 <style> 放進 HTML 的工具。Next.js App Router 則是用 useServerInsertedHTML 寫一個 registry 元件，在串流輸出 HTML 時把樣式插進去。
.attrs 與 transient props（$x）
.attrs() 可以替元件加上固定的 HTML 屬性（例如 style）。props 名稱前加 $ 表示「只給樣式用，不要傳到 DOM 上」，避免 React 警告未知屬性。
CSS 變數（custom properties）
--w: 40% 這種變數可以在 inline style 設定、在 CSS 規則裡用 var(--w) 讀取。規則固定不變，只換變數的值，不會產生新 class。

解法 A 高頻變動的值改用 inline style 或 CSS 變數

樣式規則保持固定，只讓「值」變，就不會一直產生新 class。

// 做法 1：.attrs 把常變的值放進 inline style
const Box = styled.div.attrs(p => ({
  style: { transform: `translate(${p.$x}px, ${p.$y}px)` },   // inline style：不產生新 class
}))`
  padding: 16px;                                         // 其餘樣式仍是固定的一個 class
`
<Box $x={pos.x} $y={pos.y} />                         // $ 開頭：不會被傳到 DOM

// 做法 2：規則固定讀 CSS 變數，值從 style 傳入
const Bar = styled.div`
  width: var(--w);                                       // 規則永遠只有這一條
  transition: width .2s;
`
<Bar style={{ '--w': `${percent}%` }} />

只有少數幾種固定變體（primary / secondary、size s / m / l）用插值沒問題：組合數量有限，class 產生一次就重複使用。

解法 B SSR 把樣式一起送出

伺服器渲染時收集用到的樣式、放進 HTML 的 <head>，瀏覽器第一次繪製就有樣式。

// 自訂 SSR 伺服器（或 Next.js Pages Router 的 _document）
import { renderToString } from 'react-dom/server'
import { ServerStyleSheet } from 'styled-components'

const sheet = new ServerStyleSheet()
try {
  const html = renderToString(sheet.collectStyles(<App />))   // 渲染時順便記錄用到的樣式
  const styleTags = sheet.getStyleTags()                     // 轉成 <style> 字串
  res.send(`<!doctype html><html><head>${styleTags}</head>
    <body><div id="root">${html}</div></body></html>`)  // 樣式一定要放進回應裡才有用
} finally {
  sheet.seal()                                                // 釋放資源，避免記憶體洩漏
}
// Next.js App Router：lib/registry.jsx，再用它包住 app/layout 的 children
'use client'
import { useState } from 'react'
import { useServerInsertedHTML } from 'next/navigation'
import { ServerStyleSheet, StyleSheetManager } from 'styled-components'

export default function StyledComponentsRegistry({ children }) {
  const [sheet] = useState(() => new ServerStyleSheet())   // 每個請求只建立一次
  useServerInsertedHTML(() => {                            // 串流輸出 HTML 時插入目前收集到的樣式
    const styles = sheet.getStyleElement()
    sheet.instance.clearTag()                                // 已輸出的清掉，下次只送新的
    return <>{styles}</>
  })
  if (typeof window !== 'undefined') return <>{children}</>   // 瀏覽器端不需要收集
  return <StyleSheetManager sheet={sheet.instance}>{children}</StyleSheetManager>
}

// next.config.js：啟用 SWC 編譯器支援（相當於 babel 外掛）
module.exports = { compiler: { styledComponents: true } }

解法 C 開編譯器外掛

Babel 用 babel-plugin-styled-components，Next.js 用上面的 compiler.styledComponents（SWC）。好處是SSR 兩邊 class 名稱一致（避免 hydration 不一致）、可讀的 class 名稱、壓縮模板。它不會消除執行期成本，只是減少額外負擔。

// .babelrc
{ "plugins": [["babel-plugin-styled-components", { "ssr": true, "displayName": true }]] }

解法 D 靜態樣式交給建置時產生的 CSS

大部分樣式其實不依賴 props。CSS Modules、Tailwind、vanilla-extract、Linaria 在建置時輸出 .css 檔：可被瀏覽器快取、平行下載，沒有執行期產生樣式的成本。動態的部分用 CSS 變數或切換 class。

/* Button.module.css */
.button { padding: .25em 1em; border-radius: 3px; }
.primary { background: palevioletred; color: white; }

// Button.jsx
import s from './Button.module.css'
export const Button = ({ primary, ...rest }) =>
  <button className={primary ? `${s.button} ${s.primary}` : s.button} {...rest} />   // 只切換 class，不產生 CSS

判斷 該用哪個

情境做法
拖曳座標、捲動、進度條等每幀都變的值A：inline style / CSS 變數
少數固定變體（顏色主題、尺寸）插值沒問題，或 切換 class
用 styled-components 做 SSRB + C 都要，否則 FOUC 或 class 不一致
新專案、效能敏感、大量 SSR / 靜態頁D：建置時產生 CSS
已大量使用 styled-components 的舊專案先做 A、B、C，再評估是否逐步遷移
把每幀變化的值寫進 ${p => ...}不要

取捨

  • inline style 不能寫 :hover、media query 等，這些仍要放在樣式規則裡；CSS 變數可以補足一部分。
  • 零執行期方案失去「任意 props 直接算樣式」的彈性，動態樣式要改成 CSS 變數或 class 組合；遷移大型專案成本高。
  • React 官方文件也不建議在渲染期間注入樣式，並為 CSS-in-JS 函式庫提供了 useInsertionEffect；執行期方案和 Server Components 的搭配也較麻煩（styled 元件要在 Client Component 裡）。
  • styled-components 的維護者在 2025 年宣布專案進入維護模式（以修正問題為主、不再積極開發新功能）。舊專案不必急著換，但新專案選型時值得列入考量；以官方公告為準。
  • 以上效能差異是從運作方式推論，實際影響請用 React Profiler / DevTools Performance 量測。
