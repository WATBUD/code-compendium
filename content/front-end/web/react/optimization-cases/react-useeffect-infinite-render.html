React 優化案例：useEffect 依賴物件造成重複執行 / 無限渲染

effect 每次重繪都重跑 · 結論：依賴陣列要放「穩定」的值，物件函式用 useMemo / useCallback 或改放原始值

原因

依賴陣列放了物件 / 陣列 / 函式→每次重繪都建立「新的」→React 判定依賴「變了」→effect 每次重繪都重跑→若 effect 內又 setState → 無限循環
function App() {
  const [count, setCount] = useState(0)
  const obj = { value: count }               // 每次重繪都是新物件

  useEffect(() => {
    setResult(compute(obj))                    // effect 內更新 state
  }, [obj])                                  // 依賴每次都「變」→ 重跑 → setState → 重繪 → 再重跑…
}
  1. 物件、陣列、函式用「參照」比較，每次重繪產生的都是新參照，就算內容一樣也算變了。
  2. effect 因此每次重繪都重跑。
  3. 如果 effect 內又更新 state，就會「重繪 → effect → setState → 重繪」無限循環。
更正原筆記：範例若 effect 只做 console.log，結果是「每次重繪都多印一次」，並不會無限循環；只有 effect 內會更新 state 時才會變成無限渲染。

名詞 先看懂這幾個詞

依賴陣列（dependency array）
useEffect(fn, [a, b]) 的第二個參數。React 重繪時會逐項比對 a、b 和上次是否相同，有任何一項不同才重跑 fn。
Object.is 比較
React 比對依賴用的規則，行為接近 ===：原始值比「值」，物件 / 陣列 / 函式比「是不是同一個」（參照）。所以 { a: 1 } 和另一個 { a: 1 } 算不同。
useMemo / useCallback
讓物件（useMemo）或函式（useCallback）在依賴沒變時保持同一個參照，這樣依賴陣列才不會誤判。

解法 由好到普通

① 依賴改成原始值（最簡單）

useEffect(() => {
  setResult(compute({ value: count }))         // 物件在 effect 裡面才建立
}, [count])                                  // 依賴只放原始值，只有 count 變才重跑

② 物件用 useMemo 固定參照

const obj = useMemo(() => ({ value: count }), [count])   // count 沒變就是同一個物件
useEffect(() => { setResult(compute(obj)) }, [obj])

③ 函式用 useCallback，或直接搬進 effect 裡

const logCount = useCallback(() => console.log(count), [count])
useEffect(() => { logCount() }, [logCount])

// 更簡單：只有這個 effect 用到，就直接寫在裡面，不用當依賴
useEffect(() => { console.log(count) }, [count])

判斷

情況做法
依賴是物件 / 陣列改放它裡面的原始值，或 useMemo
依賴是函式搬進 effect 裡，或 useCallback
只是把函式傳給沒有 memo 的子元件useCallback 沒有效果（子元件本來就會跟著重繪）

補充：不要為了消除警告而把依賴從陣列拿掉；要讓依賴「穩定」，而不是「隱藏」。
