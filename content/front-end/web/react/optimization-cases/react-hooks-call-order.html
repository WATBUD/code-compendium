React 優化案例：Hook 放進條件 / 迴圈就出錯

條件改變後報錯「Rendered fewer hooks than expected」或 state 對錯人 · 結論：React 靠「呼叫順序」對應每個 Hook，Hook 一律放在元件頂層、每次 render 都呼叫

原因

React 不知道 Hook 的名字，只記「第幾個」→Hook 放在 if 裡→這次 render 少呼叫一個→後面的 Hook 全部錯位 / React 直接報錯
function Profile({ showNickname }) {
  if (showNickname) {
    const [nickname, setNickname] = useState('')   // 只有條件成立時才呼叫
  }
  const [age, setAge] = useState(18)

  // 第 1 次 render（showNickname = true）：第 1 格 = nickname、第 2 格 = age
  // 第 2 次 render（showNickname = false）：age 變成「第 1 個」呼叫
  //   → 拿到的是第 1 格（nickname 的 ''），而且總數少一個 → React 報錯
}

// 迴圈也一樣：items 長度一變，Hook 的數量和順序就跟著變
items.forEach((item) => useState(item))
  1. 只靠順序對應：useState('') 沒有名字，React 只知道「這是這個元件第 N 個 Hook」，下一次 render 就把第 N 格的資料交給第 N 個呼叫。
  2. 條件 / 迴圈 / 提早 return 改變呼叫次數：少一個或多一個，後面每個 Hook 都會拿到別人的資料。React 偵測到數量不同會直接丟錯，順序換了也會在開發模式警告。
更正原筆記：原筆記說 React 把 state「存在陣列裡」並把 [值, setter] 放進去。這是好用的比喻，但實際上 React 是把每個 Hook 串成一條鏈結串列掛在元件上，按呼叫順序一個接一個往下走；而且存的是 Hook 的內部資料，不是 [值, setter] 這個陣列。結論相同：順序必須每次一樣。

名詞 先看懂這幾個詞

Hook
以 use 開頭、讓函式元件「記住東西」的函式：useState、useEffect、useRef、自訂 Hook……每個元件可以呼叫很多個。
呼叫順序（call order）
React 對應 Hook 的唯一依據。
比喻：寄物櫃沒寫名字，只有編號 1、2、3。你每次都按同樣順序去開，就能拿到自己的東西；某次跳過 1 號，你就會把 1 號的東西當成 2 號的。
頂層（top level）
元件函式本體的第一層，不在 if、迴圈、巢狀函式、try/catch 裡，也不在任何可能提早 return 的程式之後。
eslint-plugin-react-hooks
官方 lint 規則。rules-of-hooks 會在你把 Hook 放錯位置時直接標紅，建議一定要開。

解法 1 Hook 一律無條件呼叫，條件放到 Hook 裡面或 JSX

每次 render 都呼叫同樣的 Hook，只在「用不用它的值」上加條件。

function Profile({ showNickname }) {
  const [nickname, setNickname] = useState('')   // 永遠呼叫，固定是第 1 個
  const [age, setAge] = useState(18)             // 永遠是第 2 個

  useEffect(() => {
    if (!showNickname) return                     // 條件寫在 effect 裡面，不是包住 useEffect
    document.title = nickname
  }, [showNickname, nickname])

  return (
    <>
      {showNickname && <input value={nickname} onChange={(e) => setNickname(e.target.value)} />}
      <p>{age}</p>
    </>
  )
}

解法 2 需要「有時才有的 state」或「每項一份 state」→ 拆成子元件

把 Hook 搬到子元件，用條件渲染 / map 決定要不要有那個元件；每個元件各自有自己的 Hook 順序。

function NicknameField() {
  const [nickname, setNickname] = useState('')    // 在子元件頂層，順序固定
  return <input value={nickname} onChange={(e) => setNickname(e.target.value)} />
}

function Profile({ showNickname, items }) {
  return (
    <>
      {showNickname && <NicknameField />}          // 不顯示時整個元件卸載，state 一起清掉
      {items.map((item) => <Row key={item.id} item={item} />)}  // 每列在 Row 裡各自 useState
    </>
  )
}

判斷

寫法可以嗎
Hook 寫在元件 / 自訂 Hook 的頂層可以
if (x) useState()、迴圈裡 useState不要：改用解法 1 或 2
if (loading) return … 之後才呼叫 Hook不要：把所有 Hook 移到提早 return 之前
在事件處理函式、useMemo / useEffect 的 callback 裡呼叫 Hook不要：Hook 只能在 render 期間的頂層呼叫
React 19 的 use(promise / context)例外：官方允許放在條件裡
注意：拆成子元件（解法 2）時，子元件卸載 state 就會消失；如果切換顯示時想保留輸入內容，要把 state 留在父元件（解法 1）。
