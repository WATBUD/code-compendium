React 優化案例：RTK Query 的 skip 沒生效

寫了 useGetUserQuery({ skip: true }) 請求還是送出 · 結論：第一個參數是 query 的參數，選項要放第二個：useGetUserQuery(undefined, { skip })，或傳 skipToken

原因

{ skip } 寫在第一個參數→被當成 query 的參數 arg→hook 沒收到任何選項→照常發請求，skip 被忽略
// API 定義：這個 query 不需要參數
getUser: builder.query<User, void>({
  query: () => '/users/me',
}),

// 元件裡
const { data } = useGetUserQuery({ skip: !isLoggedIn })
// 這個物件是「傳給 query 的參數」，不是 hook 選項 → 未登入也會打 /users/me
  1. hook 的參數位置固定：useXxxQuery(arg, options)。第一個永遠是 arg，會原封不動交給 query(arg)，也拿來當快取的 key。
  2. 選項放錯位置不會報執行錯誤：在 JS 裡它只是被當成 arg，query 不使用它，請求照送，所以很難發現。
更正原筆記：
  • 原筆記只說放錯「會錯」。更精確的行為是：JS 不會報錯，請求照常送出，skip 和其他選項全部被忽略；若 query 的參數型別標成 void，TypeScript 才會在編譯時報錯。
  • 原筆記說略過查詢「必須」寫 undefined, { skip }。另一個官方做法是傳 skipToken，在參數可能還沒準備好時更好用（見解法 2）。

名詞 先看懂這幾個詞

builder.query
在 createApi 的 endpoints 裡定義一個「讀資料」的 API。RTK Query 會自動產生對應的 hook：getUser → useGetUserQuery。
query 參數（arg）
hook 的第一個參數，會傳給 query: (arg) => … 組出網址。它也是快取的 key：arg 不同就是不同的快取、會各自發請求。不需要參數時就是 undefined。
hook 選項（options）
hook 的第二個參數，控制 hook 本身的行為：skip（先不要發請求）、refetchOnMountOrArgChange（掛載或 arg 改變時強制重抓）、pollingInterval（定時重抓）等。
skipToken
RTK Query 提供的特殊值，放在第一個參數的位置，意思是「現在先不要查」。等條件成立時改傳真正的 arg，就會自動開始查。

解法 1 不需要參數的 query：第一個傳 undefined，選項放第二個

arg 位置明確給 undefined，選項才會被當成 options。

const { data } = useGetUserQuery(undefined, { skip: !isLoggedIn })
// 第一個：沒有參數 → undefined
// 第二個：hook 選項 → 未登入時不發請求，登入後自動開始查

解法 2 用 skipToken 取代 skip

「還不能查」直接寫在 arg 位置，特別適合「參數可能還沒準備好」的情況，TypeScript 也不會抱怨 arg 可能是 undefined。

import { skipToken } from '@reduxjs/toolkit/query/react'

// 不需要參數的 query
const { data: me } = useGetUserQuery(isLoggedIn ? undefined : skipToken)

// 需要參數的 query：getUserById: builder.query<User, string>({ query: (id) => `/users/${id}` })
const { data: user } = useGetUserByIdQuery(userId ?? skipToken)   // userId 還沒有時不查
// 一樣可以帶選項：useGetUserByIdQuery(userId ?? skipToken, { refetchOnMountOrArgChange: true })

判斷

寫法結果
useGetUserQuery()正常查詢（不需要參數）
useGetUserQuery(undefined, { skip: true })正確：略過查詢
useGetUserQuery(skipToken)正確：略過查詢
useGetUserByIdQuery(userId ?? skipToken)正確：參數還沒準備好時不查
useGetUserQuery({ skip: true })錯誤：{ skip: true } 被當成 arg，照常發請求
注意：
  • 從「查」切到 skip 時，hook 回傳的 data 會變回 undefined，畫面要能處理沒有資料的狀態。
  • arg 用物件時，RTK Query 會序列化成快取 key，內容相同就共用快取；但不要把每次都會變的值（例如時間戳）放進 arg，否則每次 render 都會重新請求。
