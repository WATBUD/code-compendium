React 優化案例：合併的 Context 值讓所有使用者一起重繪

只用到 theme 的按鈕，在 user 改變時也重繪 · 結論：Context 沒有 selector，值一變全部 consumer 重繪 → 拆 Context、useMemo 穩定 value，或改用有 selector 訂閱的 store

原因

把 theme、user 塞進同一個 Context→user 改變 → value 換成新物件→React 只比較 value 參照→所有 useContext(AppContext) 的元件都重繪
const AppContext = createContext(null)

function AppProvider({ children }) {
  const [theme, setTheme] = useState('light')
  const [user, setUser] = useState(null)
  return (
    <AppContext.Provider value={{ theme, setTheme, user, setUser }}>  // 每次 render 都是新物件
      {children}
    </AppContext.Provider>
  )
}

function ThemedButton() {
  const { theme } = useContext(AppContext)   // 只用 theme，但訂閱的是「整個 value」
  return <button className={theme}>Toggle</button>
}
// setUser(...) → value 變新物件 → ThemedButton 也重繪
  1. 沒有 selector：useContext 只能拿整個 value，React 用 Object.is 比較新舊 value，不知道你只用了其中的 theme。
  2. 合併的 value 一部分變，整個就變：user 改變 → 新物件 → 所有 consumer 都重繪。
  3. value 是內聯物件：Provider 所在元件只要重繪，即使 theme、user 都沒變，value 也是新參照，consumer 一樣全部重繪。
  4. React.memo 擋不住：consumer 是因為 Context 變了而重繪，不是因為 props，包 memo 沒有用。

以上是由 React 的比較規則推論的行為；實際影響大小要用 React DevTools Profiler 量，consumer 很少或很輕時不一定值得處理。

名詞 先看懂這幾個詞

Context / Provider / consumer
createContext() 建立一個「頻道」；<Ctx.Provider value={…}> 在樹的上方放值；底下任何呼叫 useContext(Ctx) 的元件就是 consumer，直接拿到值，不必一層層傳 props。
參照比較（Object.is）
比的是「是不是同一個物件」，不是內容。{ a: 1 } 和另一個 { a: 1 } 是兩個不同物件，比較結果是「變了」。
selector 訂閱
像 Redux 的 useSelector(state => state.theme)：元件只訂閱自己選出來的那一小塊。store 更新時，store 會重跑 selector，選出的值沒變就不重繪。這是 Context 沒有的能力。
useMemo
記住計算結果，依賴沒變就回傳同一個物件。用在 Context value 上，可以避免「Provider 重繪就產生新 value」。

解法 1 依「一起變的資料」拆成多個 Context

各自的 Context 只在自己的資料變時通知自己的 consumer。

const ThemeContext = createContext(null)
const UserContext = createContext(null)

function AppProvider({ children }) {
  const [theme, setTheme] = useState('light')
  const [user, setUser] = useState(null)
  const themeValue = useMemo(() => ({ theme, setTheme }), [theme])   // 只有 theme 變才換新物件
  const userValue = useMemo(() => ({ user, setUser }), [user])

  return (
    <ThemeContext.Provider value={themeValue}>
      <UserContext.Provider value={userValue}>{children}</UserContext.Provider>
    </ThemeContext.Provider>
  )
}

function ThemedButton() {
  const { theme } = useContext(ThemeContext)   // user 改變時不再重繪
  return <button className={theme}>Toggle</button>
}

解法 2 只有一個 Context 時，至少用 useMemo 穩定 value

value 只在內容真的變時才換參照，避免 Provider 的父元件重繪時連帶所有 consumer 重繪。

const value = useMemo(() => ({ theme, setTheme, user, setUser }), [theme, user])  // setter 本身是穩定的，不必放依賴
return <AppContext.Provider value={value}>{children}</AppContext.Provider>
// 注意：user 變了，只用 theme 的元件還是會重繪 → 要徹底解決用解法 1 或 3

解法 3 頻繁更新、大量共享 → 用有 selector 的 store

每個元件只訂閱自己選的片段，其他片段怎麼變都不重繪。

import { configureStore, createSlice } from '@reduxjs/toolkit'
import { Provider, useSelector } from 'react-redux'

const themeSlice = createSlice({
  name: 'theme',
  initialState: 'light',
  reducers: { toggle: (state) => (state === 'light' ? 'dark' : 'light') },
})

const store = configureStore({ reducer: { theme: themeSlice.reducer /* , user: userSlice.reducer */ } })

function ThemedButton() {
  const theme = useSelector((state) => state.theme)   // 只有 state.theme 變才重繪
  return <button className={theme}>Toggle</button>
}
// 根元件：<Provider store={store}><App /></Provider>
// Zustand 的 useStore(selector) 也是同一個原理

判斷

情況做法
很少變的全域設定（主題、語系、登入者）Context 就夠：一種資料一個 Context + useMemo value
同一份資料，有的元件只讀、有的只寫拆成「值」和「setter / dispatch」兩個 Context，只寫的元件不會因值改變而重繪
頻繁更新、很多元件各取一小塊Redux / Zustand 等有 selector 的 store
把所有全域狀態塞進一個 Context不要
更正原筆記：
  • 原筆記寫「useContext [React 16.3] 引入」。createContext（新版 Context API）是 16.3；useContext 這個 Hook 是 16.8 才有（和其他 Hook 一起）。
  • 原筆記說「combineReducers 讓部分狀態改變時只有相關元件重新渲染」。不對：combineReducers 只是把 reducer 拆開組合；只重繪相關元件靠的是 useSelector（或 connect）的選擇性訂閱。
  • 原筆記用 createStore。它已被標為 deprecated，官方建議改用 Redux Toolkit 的 configureStore（自動組合 reducer、內建 DevTools 與常用 middleware）。
取捨：
  • 拆 Context 會讓 Provider 一層包一層（Provider Hell），可以寫一個 AppProviders 元件把它們集中。
  • 引入 store 多一個依賴和一套概念（slice、action、selector），小專案不一定划算。
  • useSelector 預設用 === 比較選出的值；selector 每次回傳新物件 / 陣列（例如 state => ({ a: state.a })）會每次都重繪，要拆成多個 selector 或傳 shallowEqual。
