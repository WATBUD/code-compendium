React 優化案例：連續 setCount(count + 1) 只加 1

連按一次呼叫三次 setCount(count + 1)，結果只 +1 · 結論：要依「上一個值」更新，就傳函式 setCount(c => c + 1)

原因

這次 render 的 count 固定是 0（快照）→三次都算 0 + 1→三次都是「設成 1」→React 批次處理後 count = 1
const [count, setCount] = useState(0)

function handleClick() {
  setCount(count + 1)    // count 是這次 render 的快照：0 → 設成 1
  setCount(count + 1)    // count 還是 0 → 再設成 1
  setCount(count + 1)    // count 還是 0 → 又設成 1
  console.log(count)     // 印出 0：這個函式裡的 count 永遠不會變
}
// 下一次 render：count = 1，不是 3
  1. state 是快照：每次 render 拿到的 count 是一個固定的值，呼叫 setCount 不會改掉這個變數，只是「排一個更新、要求重新 render」。
  2. 三次都用同一個舊值算：count + 1 三次都是 0 + 1，等於連說三次「設成 1」。
  3. 批次處理（batching）：React 把同一個事件裡的更新收集起來，事件結束後只 render 一次。就算沒有批次，快照仍然是 0，結果一樣是 1。
更正原筆記：
  • 原筆記只說「setState 是異步的」。更準確的說法是：更新會排隊到之後才 render，而這次 render 的 state 是快照、不會變。它不是 Promise，await setCount(...) 也拿不到新值。
  • 原筆記建議「要在 state 更新後執行某些操作，用 useEffect 監聽」。這通常是多繞一圈：多一次 render、邏輯被拆散。直接先算出新值，再拿新值去用（見下方解法 2）。useEffect 只留給「和外部系統同步」的情況。
  • 原筆記範例 useState(0);s 多了一個 s，是語法錯誤。

名詞 先看懂這幾個詞

快照（snapshot）
每次 render，元件函式重新執行一次，拿到「這一輪」的 state。這輪裡的 count 就是一個普通的 const，從頭到尾不會變。
比喻：像拍照，照片拍下的是當下的樣子，之後現場怎麼變，照片都不會跟著變。
更新佇列（queue）
呼叫 setCount(x) 時，React 先把「要改成 x」記在佇列裡，等事件處理完，再依序套用佇列裡的每一筆，算出下一輪的 state。
批次處理（batching）
同一個事件裡的多次 setState 合併成一次 render，避免中間狀態被畫出來、也省掉多餘的 render。React 18 起，setTimeout、Promise 裡的更新也會自動批次。
更新函式（updater function）
傳給 setter 的函式，例如 c => c + 1。React 套用佇列時，會把「前一筆更新後的值」當參數傳進去，所以可以一筆接著一筆累加。

解法 1 依前一個值更新 → 用更新函式

每一次都拿「佇列中最新的值」來算，三次就是 0 → 1 → 2 → 3。

function handleClick() {
  setCount(c => c + 1)   // 佇列：0 → 1
  setCount(c => c + 1)   // 拿上一筆的結果：1 → 2
  setCount(c => c + 1)   // 2 → 3
}
// 下一次 render：count = 3

解法 2 更新後還要用到新值 → 先算好再用

不要等 state 變了再用 useEffect 去接，在事件裡先算出新值，存成變數，設定和後續邏輯都用它。

function handleClick() {
  const next = count + 1        // 自己算出下一個值
  setCount(next)                  // 排入更新
  console.log(next)               // 立刻拿得到新值，不必等 render
  if (next >= 10) alert('到上限了') // 後續邏輯也用 next，不必另寫 useEffect
}

判斷

情況寫法
新值跟舊值無關（例如 setName(input)）直接傳值
新值由舊值算出，且同一事件可能更新多次、或在 callback / timer 裡更新更新函式 c => c + 1
更新後馬上要用到新值先算出 next 再用；不要為此加 useEffect
想在 setState 後立刻讀 count讀不到，這輪的 count 是舊快照
注意：
  • 更新函式必須是純函式（只根據參數回傳新值、不做副作用）。開發模式的 StrictMode 會刻意呼叫兩次來檢查。
  • 物件 / 陣列 state 一樣要回傳新的物件：setUser(u => ({ ...u, age: u.age + 1 }))，不要直接改 u。
