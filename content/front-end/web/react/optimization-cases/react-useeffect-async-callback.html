React 優化案例：useEffect 不能直接傳 async 函式

寫 useEffect(async () => …) 被 lint / React 警告 · 結論：effect 本身保持同步，在裡面定義 async 函式再呼叫，並用旗標擋掉過期結果

原因

effect 寫成 async→async 函式一定回傳 Promise→React 期待「undefined 或清理函式」→拿不到清理函式，清理邏輯失效
useEffect(async () => {
  const data = await fetchUser(userId)
  setUser(data)

  return () => { /* 想在這裡清理 */ }   // 實際上 React 收到的是 Promise，不是這個函式
}, [userId])
  1. 回傳值不對：useEffect 的函式只能回傳 undefined 或一個清理函式；async 函式永遠回傳 Promise。開發模式下 React 會在 console 警告。
  2. 清理函式被包進 Promise：return () => … 變成 Promise 的結果，React 不會去 await 它，所以卸載或依賴改變時清理永遠不會執行。
更正原筆記：
  • 原筆記說「在 effect 內定義 async 函式並呼叫」就能避免競態。不對：這個寫法只修好「回傳值」的問題。userId 快速改變時，舊請求晚回來一樣會蓋掉新資料，元件卸載後也還會 setState。要再加 ignore 旗標或 AbortController（見下方解法，以及「useEffect 請求競態與 AbortController」案例）。
  • 原筆記說 .then()「兼容舊瀏覽器」。這不是理由：async/await 會由 Babel / TypeScript 依目標瀏覽器轉譯，現代專案不必為此改用 .then()。兩種寫法都只是處理 Promise 的語法，競態問題一樣存在，選哪個看可讀性即可。

名詞 先看懂這幾個詞

async 函式
前面加 async 的函式，呼叫後立刻回傳一個 Promise，裡面的 await 只是「暫停這個函式」，不會讓呼叫它的人等。所以 React 呼叫 effect 後馬上拿到的是 Promise。
清理函式（cleanup）
effect 回傳的函式。下一次 effect 執行前、或元件卸載時，React 會先呼叫它。用來取消訂閱、清 timer、忽略過期的請求。
競態（race condition）
結果取決於「誰先完成」，而順序不可控。例如 userId 1 → 2，請求 1 比請求 2 慢回來，畫面最後顯示 1 的資料。
IIFE（立即執行函式）
定義完馬上呼叫的函式：(async () => { … })()。效果和「先命名再呼叫」一樣，只是少一個名字。

解法 effect 保持同步，async 放裡面，清理時標記過期

effect 本身不加 async，回傳清理函式；清理時把 ignore 設成 true，過期的結果就不寫入。

useEffect(() => {                          // effect 本身是同步函式
  let ignore = false                       // 這一輪 effect 專屬的旗標

  async function load() {                  // async 放在裡面，await 照常用
    const data = await fetchUser(userId)
    if (!ignore) setUser(data)            // 已過期（userId 變了 / 卸載）就不寫入
  }
  load()                                   // 呼叫它；回傳的 Promise 不交給 React

  return () => { ignore = true }          // 下一輪開始前 / 卸載時，標記這輪過期
}, [userId])

能取消的請求（fetch）更好的做法是用 AbortController，直接把舊請求中止，連網路都省掉；細節見「useEffect 請求競態與 AbortController」案例。

判斷

寫法結果
useEffect(async () => …)不要：回傳 Promise，清理失效
effect 內定義 async 函式 / IIFE / .then()，沒有清理回傳值正確，但仍有競態
同上 + ignore 旗標正確，適合任何 Promise
同上 + AbortController正確且會中止請求，適合 fetch / axios
需要快取、重試、去重改用資料請求庫（React Query / SWR / RTK Query）
注意：
  • ignore 旗標只是「不寫入結果」，請求本身還是會跑完；要省網路就用 AbortController。
  • 開發模式的 StrictMode 會刻意執行 effect → 清理 → 再執行，第一輪的結果被忽略是正常的。
