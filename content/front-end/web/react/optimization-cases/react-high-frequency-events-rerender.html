React 優化案例：高頻事件造成的整頁重繪

滑鼠提示框 / 虛擬列表捲動卡頓 · 結論：高頻、只影響位置的值，不要放進 state

原因

mousemove / scroll 每秒數十～上百次→setState（值每次都不同）→最上層大元件整個重繪→所有列與子元件重新比對→主執行緒被佔滿 → 卡
// 提示框：位置存在 state
onMouseMove={(e) => setRowTip({ text, x: e.clientX, y: e.clientY })}

// 虛擬列表：捲動位置存在 state
el.addEventListener('scroll', () => setRemoteScrollTop(el.scrollTop))
  1. 值每次都不同（座標、scrollTop），React 的「值相同就略過」派不上用場。
  2. state 在最上層，重繪範圍 = 整個元件（所有 branch 列、commit 列、子元件）。
  3. 列元件沒有 React.memo，每次都重新建立元素與 onClick / style 物件。

名詞 先看懂這幾個詞

高頻事件
使用者操作期間不斷觸發的事件：mousemove（滑鼠每動一下）、scroll（每捲一下）。每秒可能幾十到上百次，處理函式也跟著被呼叫這麼多次。
state 與重繪（re-render）
setState 一呼叫，React 就會重新執行該元件的函式（以及它底下的子元件），再把結果和上次比較、更新畫面。重新執行函式本身就有成本，即使最後畫面沒變。
為什麼「值相同就略過」幫不上忙
React 發現新舊 state 完全相同時會直接略過這次更新。但座標、scrollTop 幾乎每次都不同，傳物件也每次是新參照，所以永遠略不過。
ref（useRef）
一個「改了不會觸發重繪」的盒子，ref.current 可以存任何東西（常用來存 DOM 元素）。拿到 DOM 元素後，就能繞過 React 直接改它。
transform / translate3d
CSS 的位移屬性。只改 transform 不會重新計算版面（不用重新排版，由 GPU 合成），所以拿來做「跟著游標移動」最便宜。top / left 則會觸發排版。
will-change
提示瀏覽器「這個屬性等一下會一直變」，讓它預先準備（建立獨立圖層）。只該用在真的會頻繁變動的元素。
虛擬列表（virtualization）
清單很長時，只把「畫面上看得到的幾列」畫出來，其餘不畫；捲動時換掉那幾列。畫面上要換哪幾列是由 React 決定的，所以捲動位置必須讓 React 知道。
overscan（緩衝列數）
在可視範圍的上下多畫幾列，讓捲動時不會看到空白。
量化（snap）與 bail out
把連續的值「對齊」成階梯（每 4 列才算一階）。React 看到同一階的值相同就略過更新（bail out）。
Portal
createPortal 讓元件把內容畫到 DOM 的另一個位置（如 document.body），不受原本父層的位置、裁切影響。提示框用它，才不會被側邊欄蓋住。

解法 A 提示框：不進 state，用 ref 直接改 DOM

位置只影響提示框自己 → ref + transform，零次重繪

const rowTipRef = useRef(null)                       // 指向提示框的 DOM 元素

const moveRowTip = useCallback((e) => {
  const el = rowTipRef.current
  if (!el) return
  const x = Math.min(e.clientX + 12, window.innerWidth - 300)      // 不超出右邊界
  el.style.transform = `translate3d(${x}px, ${e.clientY + 18}px, 0)`   // 只改位置，不觸發排版
}, [])

const showRowTip = useCallback((e, text) => {
  const el = rowTipRef.current
  if (!el) return
  el.textContent = text                                // 換文字
  moveRowTip(e)
  el.style.display = 'block'
}, [moveRowTip])

const hideRowTip = useCallback(() => {
  if (rowTipRef.current) rowTipRef.current.style.display = 'none'
}, [])

// 列上：進入時換文字，移動時只改位置，離開時隱藏
<div onMouseEnter={(e) => showRowTip(e, text)} onMouseMove={moveRowTip} onMouseLeave={hideRowTip} />

// 全域只渲染一次（portal 到 body，不被側邊欄蓋住）
<ModalPortal><div ref={rowTipRef} className="rowTip" /></ModalPortal>
/* 用 transform 定位，並預先告知瀏覽器 */
.rowTip { position: fixed; top: 0; left: 0; display: none;
          pointer-events: none; will-change: transform; z-index: 6000; }

解法 B 虛擬列表：state 量化，讓 React 能略過

畫哪幾列必須由 React 決定，不能純 ref → state 只存「對齊 N 列的視窗起點」，N 列才變一次

const ROW_H = 26, OVERSCAN_ROWS = 8
const STEP = Math.floor(OVERSCAN_ROWS / 2)                 // 4 列

const [windowStart, setWindowStart] = useState(0)
el.addEventListener('scroll', () =>
  setWindowStart(Math.floor(el.scrollTop / ROW_H / STEP) * STEP))   // 值相同 → React 略過

// 繪製範圍：往前多畫 OVERSCAN，往後多畫「視窗高度 + OVERSCAN」
const first = Math.max(0, windowStart - OVERSCAN_ROWS)
const last  = Math.min(total - 1,
  windowStart + STEP + Math.ceil(viewportH / ROW_H) + OVERSCAN_ROWS)
STEP 必須 ≤ OVERSCAN_ROWS，否則量化誤差吃掉緩衝，邊緣會露白。
為什麼不會露白：真正的可視起點落在 [start, start + STEP) 之間，往前多畫 OVERSCAN 列一定涵蓋；往後同理。

判斷

  • 改變畫什麼 → state
  • 只改變某元素的位置 / 樣式 → ref + 直接改 DOM
  • 高頻又必須影響畫面 → 量化 / 節流後再進 state

補充：先用 React DevTools Profiler 量測，再動手（此案例的原因是從程式結構推論，並非實測）；其餘可再做：列元件 React.memo、避免每次新建 []、長清單分批渲染。
