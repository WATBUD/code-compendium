React 優化案例：量測 DOM 後再定位會閃一下 → useLayoutEffect

Tooltip / 彈窗先出現在錯的位置再跳到對的位置 · 結論：「量測 DOM → setState 改位置」要放在 useLayoutEffect，在瀏覽器繪製前完成

原因

第一次 render：還不知道高度，用預設位置→瀏覽器先把這個錯的位置畫出來→useEffect 量測高度 → setState→再 render、再畫一次 → 看到跳動
import { useEffect, useRef, useState } from 'react'

function Tooltip({ targetTop, children }) {
  const ref = useRef(null)
  const [height, setHeight] = useState(0)          // 第一次 render 還不知道真實高度

  useEffect(() => {                                // 在瀏覽器「已經畫出畫面」之後才執行
    setHeight(ref.current.getBoundingClientRect().height)
  }, [])

  // 第一幀：height = 0 → 位置錯；量到後第二幀才移到 targetTop 正上方
  return <div ref={ref} style={{ position: 'absolute', top: targetTop - height }}>{children}</div>
}
  1. useEffect 在繪製之後才跑：React 把 DOM 更新完，瀏覽器通常已經先畫了一幀，effect 才執行。
  2. 畫面要靠量測結果決定：第一幀只能用預設值（height = 0），使用者會看到一幀錯誤位置，然後跳到正確位置。
更正原筆記：
  • 原筆記說 useEffect「在瀏覽器閒暇時間（idle time）執行」。不準確：React 不是等瀏覽器閒下來，而是在 commit 之後排程執行，通常在瀏覽器繪製之後。由使用者操作（例如點擊）觸發的更新，React 18 起甚至可能在繪製前就同步執行完 effect。重點是：useEffect 不保證在繪製前跑，useLayoutEffect 保證。
  • 原筆記範例用了 useState 卻只 import { useEffect }，少 import useState（本頁範例已補上）。

名詞 先看懂這幾個詞

繪製（paint）
瀏覽器把算好的版面真正畫到螢幕上的那一步。畫出來的那一幀使用者就看得到，哪怕只有十幾毫秒。
React 更新的順序
  1. render：執行元件函式，算出要長怎樣。
  2. commit：把變更寫進真實 DOM。
  3. useLayoutEffect 執行（DOM 已更新、畫面還沒畫）。這裡 setState，React 會在繪製前同步再 render 一次。
  4. 瀏覽器繪製。
  5. useEffect 執行（一般情況）。
量測 DOM（layout 讀取）
例如 getBoundingClientRect()、offsetHeight，讀出元素實際的大小與位置。只有 DOM 真的放進畫面後才量得到，所以只能在 effect 裡做。
阻塞繪製
useLayoutEffect 裡的程式跑完之前，瀏覽器不會畫下一幀。跑得久，整個畫面就會卡住。

解法 換成 useLayoutEffect，在繪製前量好、改好

量測和 setState 都在繪製前完成，使用者只會看到最終位置。

import { useLayoutEffect, useRef, useState } from 'react'

function Tooltip({ targetTop, children }) {
  const ref = useRef(null)
  const [height, setHeight] = useState(0)

  useLayoutEffect(() => {                          // DOM 已更新、瀏覽器還沒畫
    setHeight(ref.current.getBoundingClientRect().height)   // 這裡 setState 會在繪製前同步重 render
  }, [])

  // 第一幀畫出來時，height 已經是真實高度 → 不會跳
  return <div ref={ref} style={{ position: 'absolute', top: targetTop - height }}>{children}</div>
}

判斷

情況用哪個
要先量 DOM（大小、位置、捲動）再決定畫面長相useLayoutEffect
打 API、訂閱、log、設定 timeruseEffect；不要用 useLayoutEffect，會白白阻塞繪製
閃爍其實來自資料還沒回來（loading）useLayoutEffect 救不了，要處理 loading 畫面或預先取資料
只是要算衍生值（不需量 DOM）兩個都不用，直接在 render 裡算
取捨：
  • 會阻塞繪製：裡面的程式和它觸發的重 render 都在畫面出現前跑完，太重會讓畫面卡頓。只放「量測 + 改位置」這種輕量工作。
  • 伺服器端渲染（SSR）時 useLayoutEffect 不會執行；需要 SSR 的元件要另外處理（例如只在客戶端掛載後才顯示 tooltip）。
