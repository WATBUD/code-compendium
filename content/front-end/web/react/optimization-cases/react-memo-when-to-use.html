React 優化案例：React.memo 何時有用、何時不該用

memo 加了卻沒效，甚至更慢 · 結論：props 穩定、元件夠重、比較夠便宜，才值得用

原因

父元件重繪→所有子元件跟著重繪→加上 React.memo 想跳過→但 props 每次都是新的 / 比較太貴 / 元件太輕→memo 沒效，甚至更慢
  1. props 每次都是新參照（內聯的 {...}、() => …、[]）→ 淺比較永遠判定「變了」，memo 白包。
  2. 自訂比較函式太貴（例如 JSON.stringify 深比較）→ 比較的成本抵銷省下的重繪。
  3. 元件本身很輕→ 重繪幾乎免費，memo 反而多了「記住上次 props 與結果」的記憶體和比較成本。
const Child = React.memo(({ style }) => <div style={style} />)

function Parent() {
  return <Child style={{ color: 'red' }} />       // 每次重繪都是新物件 → memo 永遠不生效
}

名詞 先看懂這幾個詞

React.memo
包住元件：props 沒變就跳過這次重繪，沿用上次的結果。
淺比較（預設）
逐項用 Object.is 比較 props 的第一層。只比較「每個 prop 本身」是不是同一個，成本很低，通常可以忽略。
自訂比較函式 areEqual
React.memo(Comp, areEqual) 的第二個參數。回傳 true = props 相同 → 跳過重繪；false = 不同 → 重繪。一旦提供，React 就完全依賴它，不再做預設的淺比較。（注意跟 class 元件的 shouldComponentUpdate 回傳值意思相反。）

解法 先判斷該不該用，再用對

// 1) 預設淺比較：先讓傳進去的 props 保持穩定
const STYLE = { color: 'red' }                        // 模組常數
const Child = React.memo(({ style }) => <div style={style} />)
<Child style={STYLE} />                              // 參照不變 → 跳過重繪

// 2) 只有在「只關心部分 props」時才自訂比較，而且比較要便宜
const areEqual = (prev, next) => prev.value === next.value   // 只比較需要的欄位
const Row = React.memo(RowImpl, areEqual)

// 避免：const areEqual = (p, n) => JSON.stringify(p) === JSON.stringify(n)   // 深比較，成本高

判斷

情況要不要 memo
列表項目、重繪成本高的子元件，且父元件常重繪要，並穩定 props
props 本來就每次都會變（即時資料、動畫）不要，跳過不了
很輕量的元件（幾個文字、按鈕）不必
想用自訂比較只比必要欄位；不要深比較整個 props

原則：先用 React DevTools Profiler 找出真正慢的元件再加；memo 是「有證據才加」的優化。穩定 props 的做法見「React.memo + 穩定參照」案例。
