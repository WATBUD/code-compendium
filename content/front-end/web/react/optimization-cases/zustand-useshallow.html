React 優化案例：Zustand selector 與 useShallow

selector 回傳新物件造成多餘重繪 · 結論：回傳新物件的 selector 要包 useShallow，或拆成一個值一個 hook

原因

selector 回傳新物件 { a, b }→每次執行都是新參照→Zustand 用參照比較判定「變了」→a、b 沒變也重繪
const { a, b } = useStore(
  (state) => ({ a: state.a, b: state.b })       // 每次執行都產生一個新物件
)
  1. store 裡任何一個值改變，selector 都會重新執行。
  2. 每次都回傳新物件，Zustand 預設比較「是不是同一個參照」，永遠判定為「變了」。
  3. 結果：a、b 都沒變，元件仍然重繪。（a、b 真的改了就重繪，是合理的，不算問題。）
更正原筆記：Zustand v5 起對這種寫法更嚴格：selector 每次回傳新參照，可能直接造成「無限重繪」的錯誤；官方建議用 useShallow。另外 v5 的 useStore 已不再接受第二個比較函式參數，原筆記推薦的 useStore(selector, shallow) 寫法在 v5 不適用。

名詞 先看懂這幾個詞

selector
傳給 useStore 的函式，從整個 store 挑出元件要用的那一小塊。元件只在「挑出來的結果變了」才重繪。
參照比較 vs 淺比較（shallow）
參照比較：看是不是同一個物件。淺比較：逐一比較物件的第一層屬性值，每個值都相同就算相同，即使物件本身是新的。
useShallow
Zustand 提供的 hook，把你的 selector 包起來，讓它的回傳值用「淺比較」判斷是否變了。

解法 三種寫法

① 推薦：useShallow 包住 selector

import { useShallow } from 'zustand/react/shallow'

const { a, b } = useStore(
  useShallow((state) => ({ a: state.a, b: state.b }))       // a、b 的值沒變 → 不重繪
)

② 最簡單：一個值一個 hook

const a = useStore((state) => state.a)       // 回傳原始值，天然穩定
const b = useStore((state) => state.b)

③ 舊寫法（v4 以前）：第二個參數傳 shallow

import { shallow } from 'zustand/shallow'
const { a, b } = useStore((state) => ({ a: state.a, b: state.b }), shallow)   // v5 不適用
// v5 要自訂比較時：import { createWithEqualityFn } from 'zustand/traditional'

判斷

selector 回傳需要 useShallow 嗎
單一原始值（數字、字串、布林）不需要
store 裡既有的物件 / 函式（直接取出，不是新建）不需要（參照本來就穩定）
每次新建的物件 / 陣列（{ a, b }、.map()、.filter()）需要
