前端優化案例：Bundle 體積過大

打包產物太大、首屏載入慢 · 結論：先分析，再用 Tree Shaking、Code Splitting、壓縮、精簡依賴逐項縮小

原因

打包產物（bundle）太大→瀏覽器要下載、解析、執行更多 JS→首屏變慢、行動裝置 / 慢網更明顯→記憶體用量也增加
  1. 打包了用不到的程式碼（整個函式庫只用一個函式）。
  2. 所有頁面的程式碼擠在同一個檔案，進首頁就下載全站。
  3. 未壓縮、重複依賴、體積大的第三方套件、不必要的 polyfill。

名詞 先看懂這幾個詞

Bundle
打包工具（webpack、Vite、Rollup、Parcel）把你的 JS / CSS / 資源合併成的檔案。使用者載入頁面就是在下載它。
Tree Shaking
打包時自動移除沒被用到的 export。前提：使用 ES Module 的 import / export（靜態分析得出誰被用到），且套件沒有副作用。
Code Splitting（程式碼分割）
把 bundle 切成多個檔案，用到時才下載。入口是動態 import()。
Minification / Compression
Minify：去掉空白與註解、縮短變數名稱（Terser）。Compression：傳輸時用 gzip / Brotli 壓縮。兩者可疊加。
Polyfill 與 Babel
Babel 轉換新語法（箭頭函式 → 舊寫法）；Polyfill 補上舊瀏覽器沒有的 API（Promise、fetch）。只補目標瀏覽器真正缺的，才不會讓 bundle 變大。

解法

① Tree Shaking：只引入需要的

import _ from 'lodash'                      // 整個函式庫都進 bundle
import { debounce } from 'lodash-es'        // ES Module 版本，只留 debounce

② Code Splitting：動態 import 與路由層分割

// 按下才載入
btn.addEventListener('click', async () => {
  const mod = await import('./heavyModule.js')
  mod.default()
})

// React：每個頁面獨立一包，進到那頁才下載
const Home = lazy(() => import('./Home'))
const About = lazy(() => import('./About'))
// <Suspense fallback={<Loading />}><Routes>…</Routes></Suspense>
// webpack：自動把共用模組抽成獨立 chunk
optimization: { splitChunks: { chunks: 'all' } },
output: { filename: '[name].[contenthash].js', chunkFilename: '[name].[contenthash].chunk.js' }

③ 壓縮

正式環境啟用 minify（webpack / Vite 預設已開），伺服器 / CDN 啟用 gzip 或 Brotli。

④ 精簡依賴與 polyfill

// 用 browserslist 指定目標瀏覽器，Babel 只補真的缺的 polyfill
["@babel/preset-env", { "useBuiltIns": "usage", "corejs": 3 }]
  • 換更小的替代品（例：moment → dayjs / date-fns）。
  • 定期移除 package.json 裡沒用到的依賴。

⑤ 先分析，再優化

用 webpack-bundle-analyzer（webpack）或 rollup-plugin-visualizer（Vite / Rollup）畫出每個模組的大小，從最大的開始處理。

⑥ 外部化（external）大型套件：有取捨

// webpack：React 不打包，改由頁面另外載入
externals: { react: 'React', 'react-dom': 'ReactDOM' }
取捨：externals 會讓你依賴外部 CDN（失效就整站壞）、要自己確保版本一致，現代專案更常用「程式碼分割 + 長效快取」取代。若使用 CDN，請務必使用可信來源並加上 SRI 完整性檢查。
更正原筆記：原筆記建議用 polyfill.io 的 CDN 腳本。該網域在 2024 年被轉手後曾被用來散布惡意程式碼，不要使用；請改用 Babel + core-js 只打包需要的 polyfill，或使用自己控制 / 可信的來源。
