JavaScript 優化案例：延遲載入 (Lazy Loading)

一進頁面就載入全部資源 · 結論：首屏外、暫時用不到的，等快用到才載入

原因

頁面一開啟→圖片 / JS / 影片 / 資料全部一起載入→搶頻寬、阻塞首屏→載入慢、浪費流量（使用者可能根本沒看到）
// 原本：進頁面就全部載入
<img src="photo-001.jpg"> … <img src="photo-200.jpg">     // 200 張圖同時請求
import { HeavyChart } from './HeavyChart'                  // 即使使用者不打開圖表也先下載
  1. 很多內容在首屏之外，使用者要捲很久才會看到，甚至永遠不會。
  2. 大量請求跟首屏重要資源搶頻寬，主要內容反而變慢。
  3. 行動網路下流量與電量都被浪費。

名詞 先看懂這幾個詞

首屏（above the fold）
使用者打開頁面不用捲動就看得到的範圍。首屏內的內容要盡快載入，首屏外的才適合延後。
Lazy Loading（延遲載入）
資源「快要用到時才載入」，而不是一開始全部載入。
IntersectionObserver 與哨兵元素
瀏覽器內建的「某元素有沒有進入畫面」偵測器。在清單底部放一個哨兵元素（沒內容的小元素），哨兵進入畫面 = 快到底了，該載入下一批。比自己監聽 scroll 並計算位置省效能。
動態 import（code splitting）
import("./x.js") 會回傳 Promise，執行到這行才下載該模組。打包工具會自動把它切成獨立的檔案。

解法 依資源類型選對方法

① 圖片、iframe：原生 loading="lazy"

<img src="photo.jpg" loading="lazy" width="400" height="300" alt="...">
<iframe src="map.html" loading="lazy"></iframe>

只有 img 和 iframe 支援；請同時寫 width / height（或 aspect-ratio）預留空間，避免圖片載入後把版面撐開（版面位移 CLS）。

② 無限捲動：IntersectionObserver + 哨兵

// 原本：每個 scroll 事件都要量位置，高頻又吃效能
window.addEventListener('scroll', () => {
  if (window.innerHeight + window.scrollY >= document.body.offsetHeight) loadMore()
})

// 改用：哨兵進入畫面才載入
const io = new IntersectionObserver((entries) => {
  if (entries.some((e) => e.isIntersecting)) loadMore()
}, { rootMargin: '300px' })             // 提早 300px 開始載入，使用者不會看到空白
io.observe(document.querySelector('#sentinel'))

③ JavaScript 模組：動態 import

button.addEventListener('click', async () => {
  const { HeavyChart } = await import('./HeavyChart.js')   // 按下才下載
  render(HeavyChart)
})

// React：const Chart = React.lazy(() => import('./HeavyChart'))  搭配 <Suspense>

④ 影片：preload="none" + poster

<video preload="none" poster="cover.jpg" controls>
  <source src="video.mp4" type="video/mp4">
</video>

⑤ 網頁字型：font-display，而不是 preload

@font-face {
  font-family: 'Roboto';
  src: url('roboto.woff2') format('woff2');
  font-display: swap;      // 字型沒載好先用系統字型，載好再換，不阻塞文字顯示
}
更正：常見的兩個錯誤寫法——
① <video loading="lazy"> 無效，loading 屬性只支援 img 與 iframe；影片請用 preload="none"。
② <link rel="preload"> 是「提早載入」重要資源，不是延遲；想延後字型請用 font-display。

判斷

資源做法
首屏內的圖片（尤其最大那張）不要 lazy，它是 LCP；要用 fetchpriority="high" 或提早載入
首屏外的圖片 / iframeloading="lazy"
長清單、無限捲動IntersectionObserver + 哨兵
使用者不一定會用到的功能（圖表、編輯器、彈窗）動態 import / React.lazy
影片preload="none" + poster

取捨：延遲載入會在「使用者捲到時才開始下載」造成短暫等待，可用 rootMargin 提早觸發、或用 poster / 骨架畫面（skeleton）緩衝。
