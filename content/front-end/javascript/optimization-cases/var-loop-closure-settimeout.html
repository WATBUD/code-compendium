JavaScript 觀念陷阱：for + var + setTimeout 印出五次 5

預期印出 0 1 2 3 4，實際印出 5 5 5 5 5 · 結論：var 整個迴圈只有一個 i，所有回呼共用它；改用 let，每一圈都有自己的 i

原因

var i 只有一個（函式作用域）→5 個回呼都記住「同一個 i」→迴圈同步跑完，i 變成 5→1 秒後回呼才去讀 i→5 5 5 5 5
// 原本的寫法
for (var i = 0; i < 5; i++) {        // var：整個函式（或全域）只有這一個 i
  setTimeout(() => {
    console.log(i)                     // 讀的是「執行當下」的 i，不是排程當下的值
  }, 1000)
}
// 1 秒後幾乎同時印出：5 5 5 5 5
  1. var 是函式作用域：for 的大括號不會產生新的 i，五次迭代改的是同一個變數。
  2. 箭頭函式是閉包，記住的是「變數本身」，不是當時的值。
  3. for 迴圈是同步的，會先一口氣跑完（i 停在 5），計時器的回呼要等 1 秒後才執行，那時讀到的就是 5。
  4. 為什麼「同時」印出？五個計時器幾乎在同一瞬間排程、延遲都是 1000ms，所以幾乎同時到期，一個接一個執行，看起來像一次印完。想要每秒印一個，延遲要寫成 1000 * i。
更正原筆記：原筆記說「所有回呼在同一個事件循環階段中處理」。更精確地說，每個計時器回呼都是各自獨立的 macrotask：瀏覽器每執行完一個 task 就會清空 microtask 佇列（Promise 回呼），中間也可能插入畫面更新；Node.js 雖然在同一個 timers 階段處理到期的計時器，但從 v11 起每個回呼之間也會清空 microtask。它們只是到期時間相同、接連執行而已。

名詞 先看懂這幾個詞

函式作用域 vs 區塊作用域
var 的有效範圍是整個函式，在 { } 區塊裡宣告也一樣看得到。let / const 的範圍是最近的 { }。比喻：var 是整層樓共用一塊白板，let 是每個房間各一塊。
閉包（closure）
函式會「記住」建立它時外面的變數，之後執行時去讀那個變數當下的值。五個回呼記住同一個 i，就會讀到同一個值。
setTimeout 與 macrotask
setTimeout(fn, 1000) 不會暫停程式，只是登記「1 秒後把 fn 排進任務佇列」。目前的同步程式（整個 for 迴圈）一定先跑完，fn 之後才會被當成一個獨立任務（macrotask）執行。
for 迴圈裡的 let
for (let i = ...) 有特殊規則：每一圈都建立一個新的 i，並把上一圈的值複製過來。所以每個回呼記住的是不同的 i。
IIFE（立即執行函式）
(function (j) { ... })(i)：定義完馬上呼叫。呼叫時把當下的 i 當參數傳進去，函式內的 j 是一個新的變數，等於手動為每一圈造一個作用域。在 let 出現（ES2015）之前的標準解法。

解法 A 改用 let（首選）

一個字的修改：每一圈都有自己的 i。

for (let i = 0; i < 5; i++) {        // 每次迭代建立新的 i
  setTimeout(() => console.log(i), 1000)   // 每個回呼記住自己那一圈的 i
}
// 1 秒後印出：0 1 2 3 4

解法 B IIFE（舊環境 / 只能用 var 時）

用函式參數把當下的值複製一份。

for (var i = 0; i < 5; i++) {
  (function (j) {                       // j 是每次呼叫各自的新變數
    setTimeout(() => console.log(j), 1000)
  })(i)                                 // 立即呼叫，傳入此刻的 i
}

解法 C 用 setTimeout 的額外參數傳值

setTimeout 第三個之後的參數會在排程當下被記下，執行時傳給回呼。

for (var i = 0; i < 5; i++) {
  setTimeout((n) => console.log(n), 1000, i)   // 排程時就把 i 的值傳進去
}

補充 想要每秒印一個

for (let i = 0; i < 5; i++) {
  setTimeout(() => console.log(i), 1000 * i)   // 0s、1s、2s… 各自到期
}

判斷 該用哪個

情境用
一般程式碼let（不會重新賦值的變數用 const）
必須在不支援 ES2015 的環境直接執行IIFE 或 setTimeout 額外參數
新程式碼裡用 var 宣告迴圈變數不要

注意

  • 把 let 宣告在迴圈外面：let i; for (i = 0; i < 5; i++) —— 這樣又只剩一個 i，結果一樣是五次 5。每圈新變數的規則只適用於寫在 for (let ...) 括號裡的宣告。
  • 同樣的問題不只發生在 setTimeout：迴圈裡綁事件監聽、建立 Promise 回呼，只要「之後才執行、又讀迴圈變數」都一樣。
