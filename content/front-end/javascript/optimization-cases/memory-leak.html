JavaScript 優化案例：記憶體洩漏 (Memory Leak)

用完的物件被「看不見的引用」抓著 · 結論：活得比物件久的地方，都要有對應的清理

原因

物件已經不需要了→但某處「還抓著它的參照」→垃圾回收（GC）判定它還在用→無法回收 → 記憶體越用越多 → 變慢 / 當機
  1. JavaScript 的記憶體由 GC 自動回收，但只回收「沒有任何地方引用」的東西。
  2. 洩漏不是「忘了 free」，而是不小心還留著一條引用，讓 GC 以為你還要用。
  3. 通常發生在「活得比物件久」的地方：全域、計時器、事件監聽、快取、閉包。

名詞 先看懂這幾個詞

垃圾回收（GC）與可達性
GC 從「根」（全域變數、目前的呼叫堆疊）出發，走得到的物件就保留，走不到的才回收。所以只要還有一條路走得到，物件就不會被回收。
引用（reference）
變數、陣列元素、物件屬性、閉包捕捉的變數、事件監聽的回呼……都是引用。洩漏 = 還有一條你沒注意到的引用。
閉包（closure）
函式會記住它建立時外面的變數。如果這個函式被長期保留（例如當成事件回呼），它捕捉到的大物件也跟著被保留。
WeakMap / WeakSet
把物件當 key 但不算作引用：物件在別處都沒人用了，就會被回收，條目自動消失。適合「依附在物件上的快取 / 標記」。
Heap Snapshot
Chrome DevTools 的 Memory 分頁可以為「當下的記憶體」拍照。比較前後兩張，就能看到哪些物件越來越多。

解法 常見洩漏點與修法

洩漏來源為什麼回收不了修法
意外的全域變數全域永遠可達let / const、'use strict'
計時器沒清計時器持有回呼，回呼持有外部物件clearInterval / clearTimeout
事件監聽沒移除DOM 持有監聽函式，函式持有外部物件removeEventListener / AbortController
閉包捕捉大物件長壽函式連帶保留大資料只捕捉需要的值，不需要的不要放進閉包
已移除的 DOM 仍被 JS 引用陣列 / 變數還抓著節點移除時一併清掉引用
Map 當快取無限成長key 一直被 Map 強引用WeakMap，或設上限（LRU）

計時器與事件監聽

const timer = setInterval(tick, 1000)
const ac = new AbortController()
window.addEventListener('resize', onResize, { signal: ac.signal })   // 一次取消所有綁了 signal 的監聽

function dispose() {
  clearInterval(timer)
  ac.abort()
}

React：useEffect 的清理函式

useEffect(() => {
  const id = setInterval(tick, 1000)
  window.addEventListener('resize', onResize)
  return () => {                          // 元件卸載（或依賴變動）時執行
    clearInterval(id)
    window.removeEventListener('resize', onResize)
  }
}, [])

WeakMap 與 Map 的差別

let key = { id: 1 }
const map = new Map(), weak = new WeakMap()
map.set(key, 'data')        // Map 強引用 key
weak.set(key, 'data')       // WeakMap 不算引用

key = null                  // 外面不再使用 key
// Map：條目還在 → key 物件 無法回收
// WeakMap：key 物件可被 回收，條目自動消失

偵測 用 DevTools 找洩漏

  1. 打開 DevTools → Memory 分頁，選 Heap snapshot，拍第 1 張。
  2. 重複操作你懷疑會洩漏的功能幾次（例如開關某個頁面 10 次），按垃圾桶圖示先手動 GC。
  3. 拍第 2 張，切到 Comparison 比較：數量與大小持續增加的物件就是嫌疑犯，點開看 Retainers（是誰抓著它）。

判斷

  • 物件活得比它的擁有者久（計時器、監聽、全域快取）→ 一定要有對應的清理
  • 一般區域變數離開作用域就會自動回收 → 不需要刻意設成 null；只有「長壽物件持有它」時，才需要斷開那條引用
  • 用 React → 把每個 useEffect 裡的「訂閱 / 計時器 / 監聽」都配一個清理函式
