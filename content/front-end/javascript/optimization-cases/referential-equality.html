JavaScript 優化案例：參照相等性 (Referential Equality)

物件 / 陣列 / 函式內容一樣卻不相等 · 結論：=== 比的是「同一個」，不是「一樣」

原因

物件 / 陣列 / 函式→用 === 比的是「是不是同一個」→內容一樣但不是同一個→判斷錯誤、或 React 認為「每次都變了」
{ a: 1 } === { a: 1 }        // false  內容相同，但是兩個不同的物件
[] === []                    // false
(() => {}) === (() => {})    // false

const a = { a: 1 }
const b = a
a === b                      // true   指向同一個物件
  1. 誤改共用物件：把物件賦值給另一個變數，兩者指向同一個，改一個另一個也變。
  2. 比內容失敗：=== 無法判斷「內容是否相等」。
  3. React 失效：每次重繪都新建物件 / 函式，依賴陣列、React.memo、useMemo 都認為「變了」，白白重算或重繪。

名詞 先看懂這幾個詞

原始值 vs 引用型別
原始值（數字、字串、布林、null、undefined）比的是「值」：3 === 3 為 true。
引用型別（物件、陣列、函式）變數裡存的是「記憶體位置」，=== 比的是「位置是不是同一個」。
參照（reference）
指向某個物件的「位置」。b = a 複製的是位置，不是物件本身，所以 a、b 其實是同一個物件。
淺拷貝 vs 深拷貝
淺拷貝（{ ...obj }、[...arr]）只複製第一層，裡面的巢狀物件還是共用。深拷貝（structuredClone(obj)）連巢狀都複製成新的。
Object.is
比較兩個值是否「相同」的函式，規則跟 === 幾乎一樣（差別在 NaN 與 +0 / -0）。React 判斷依賴有沒有變，用的就是 Object.is。

解法 依問題選做法

① 不想改到原物件 → 複製出新的

const user = { name: 'Alice', address: { city: 'Taipei' } }

const shallow = { ...user }                 // 只複製第一層
shallow.name = 'Bob'                          // 不影響 user
shallow.address.city = 'Tainan'               // 仍會改到 user.address（巢狀共用）

const deep = structuredClone(user)         // 連巢狀都複製
deep.address.city = 'Kaohsiung'               // 不影響 user

② 想比「內容」是否相等 → 深度比較

function deepEqual(a, b) {
  if (Object.is(a, b)) return true
  if (typeof a !== 'object' || typeof b !== 'object' || !a || !b) return false
  const ka = Object.keys(a), kb = Object.keys(b)
  if (ka.length !== kb.length) return false
  return ka.every((k) => Object.hasOwn(b, k) && deepEqual(a[k], b[k]))   // 遞迴比每一層
}
deepEqual({ a: { b: 1 } }, { a: { b: 1 } })   // true

簡化版：不處理循環參照、Date、Map、Set 等；正式使用建議 lodash 的 isEqual。不建議用 JSON.stringify 比較：key 順序不同、undefined、函式、Date 都會出錯。

③ React：讓傳進去的參照保持穩定

function Parent() {
  // 每次重繪都是新物件 / 新函式 → 子元件 memo 失效、effect 每次都重跑
  return <Child style={{ color: 'red' }} onSave={() => save()} items={[]} />
}

const STYLE = { color: 'red' }            // 模組層級常數
const EMPTY = []
function Parent() {
  const onSave = useCallback(() => save(), [])   // 函式：useCallback
  const items = useMemo(() => compute(data), [data])   // 計算結果：useMemo
  return <Child style={STYLE} onSave={onSave} items={items} />
}

判斷

需求做法
只想「是不是同一個」=== / Object.is
要複製一份獨立的淺：{...obj}；深：structuredClone
要比內容是否相等深度比較（lodash isEqual）
React 依賴 / memo 老是失效穩定參照：常數、useMemo、useCallback

延伸：這就是 React.memo 案例「要先穩定 props 才有效」的根本原因。
