JavaScript 優化案例：防抖 (Debounce) 與節流 (Throttle)

高頻事件（輸入、捲動、resize）每次都執行處理函式 · 結論：防抖 = 停下來才執行；節流 = 固定間隔最多一次

原因

事件每秒觸發數十～上百次→每次都執行處理函式→每次都打 API / 重算 / setState→請求爆量、畫面卡頓
// 原本：事件一來就做事
input.addEventListener('input', (e) => fetchSuggestions(e.target.value))   // 每按一鍵送一次請求
window.addEventListener('resize', recalcLayout)                              // 拖曳視窗每秒上百次
  1. 使用者打字時，每按一鍵就送一次請求，絕大多數請求在回來前就已經過期。
  2. scroll、resize、mousemove 是高頻事件，處理函式再重也會被連續呼叫。
  3. 真正需要的只是「停下來之後的結果」或「每隔一段時間的更新」。

名詞 先看懂這幾個詞

高頻事件
瀏覽器在使用者操作期間不斷觸發的事件，例如 input（每次輸入）、scroll、resize、mousemove。處理函式的執行次數 = 事件次數。
setTimeout / clearTimeout
setTimeout(fn, 300) = 300ms 後執行 fn，會回傳一個計時器 id；clearTimeout(id) = 在它執行前取消。防抖就是靠「不斷取消、重新計時」做到的。
閉包（closure）
函式可以「記住」它被建立時外面的變數。debounce 回傳的函式一直記著 timer 這個變數，所以能在下一次呼叫時取消上一次的計時器。
...args 與 func.apply(this, args)
把收到的參數與 this 原封不動轉交給真正的處理函式，包裝後的行為才跟原本一致。

解法 A 防抖 Debounce：停下來才執行

每次觸發都取消上一次的計時、重新計時；連續觸發時永遠等不到計時結束，直到停止觸發 delay 毫秒後才執行一次。

function debounce(func, delay) {
  let timer                                      // 閉包記住上一次的計時器
  return function (...args) {
    clearTimeout(timer)                            // 取消上一次還沒執行的
    timer = setTimeout(() => func.apply(this, args), delay)   // 重新計時
  }
}

const handleSearch = debounce((query) => fetchSuggestions(query), 500)
input.addEventListener('input', (e) => handleSearch(e.target.value))

解法 B 節流 Throttle：固定間隔最多一次

不管觸發多頻繁，在 limit 毫秒內最多只執行一次。適合「持續進行中、需要定期更新」的情況。

function throttle(func, limit) {
  let lastCall = 0                               // 上次真正執行的時間
  return function (...args) {
    const now = Date.now()
    if (now - lastCall >= limit) {                  // 距離上次夠久了才放行
      lastCall = now
      func.apply(this, args)
    }
  }
}

window.addEventListener('scroll', throttle(updateProgressBar, 200))
注意：這個簡易版只會在「間隔開始時」執行（leading），最後一次觸發可能被丟掉（例如停在頁面最底端時沒有最後一次更新）。需要保證最後一次也執行時，要加 trailing 處理，或直接用 lodash 的 throttle / debounce。

判斷 該用哪個

情境用原因
搜尋框輸入、表單即時驗證防抖只在乎「打完之後」的結果
視窗 resize 後重新計算版面防抖拖曳過程中間值沒有意義
捲動進度、無限捲動判斷、拖曳中更新節流過程中要定期更新，不能等停下來
按鈕防連點（下單、送出）節流（只執行第一次）第一次要立即生效，之後一段時間內忽略
要「跟著游標走」的 UI（提示框）都不適合節流會顯得卡頓；應改為不經 React state 直接改 DOM

React 在元件裡的注意事項

// 錯誤：每次重繪都建立「新的」debounce 函式 → 計時器各自獨立，防抖失效
function Search() {
  const onChange = debounce((v) => search(v), 500)
  return <input onChange={(e) => onChange(e.target.value)} />
}

// 正確：用 useMemo 讓同一個防抖函式跨重繪保持不變
function Search() {
  const onChange = useMemo(() => debounce((v) => search(v), 500), [])
  return <input onChange={(e) => onChange(e.target.value)} />
}

原因與「參照相等性」「React.memo」案例是同一件事：每次重繪都產生新的函式 = 新的參照。
