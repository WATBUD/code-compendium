JavaScript 常見錯誤：用 || 或三元運算子給預設值，把 0 和 "" 吃掉

使用者明明輸入 0、空字串或 false，卻變成預設值 · 結論：只想處理「沒有值」（null / undefined）就用 ??

原因

x || d / x ? x : d 判斷的是真假值→0、""、false、NaN 都算 falsy→被當成「沒有值」→有效輸入被換成預設值
// 原本的寫法
const count = input.count || 10                         // count = 0 → 變成 10
const name  = user.nickname ? user.nickname : '匿名'      // 使用者故意清空 "" → 變成 '匿名'
const muted = options.muted || true                      // 傳 false → 變成 true，永遠關不掉
  1. || 是最常見的元凶：它在左邊為 falsy 時就回傳右邊，而不是只在「沒有值」時。
  2. x ? x : d 和 x || d 行為完全一樣，只是寫得比較長。
  3. 0（數量、價格、音量）、""（使用者清空的欄位）、false（關閉的開關）都是合法的值，卻被當成沒填。

名詞 先看懂這幾個詞

falsy（假值）
放進 if 會被當成 false 的值：false、0、-0、0n、""、null、undefined、NaN。其他都是 truthy（包括 "0"、[]、{}）。
nullish
只有 null 和 undefined 兩個，意思是「真的沒有值」。是 falsy 的子集合。
??（Nullish Coalescing，空值合併）
a ?? b：只有 a 是 null 或 undefined 時才回傳 b，其他（包括 0、""、false）都保留 a。ES2020 加入。
?.（Optional Chaining）
user?.settings?.volume：中間任何一層是 null / undefined 就直接得到 undefined，不會報錯。常和 ?? 搭配。
??=
a ??= b 等於 a ?? (a = b)：只有 a 是 null / undefined 時才賦值。ES2021 加入。

解法 A 改用 ??

只在真的沒有值時才套預設。

const count = input.count ?? 10              // 0 保留，只有沒傳才是 10
const name  = user.nickname ?? '匿名'         // "" 保留
const muted = options.muted ?? true          // false 保留

解法 B 深層屬性：?. 加 ??

const volume = user?.settings?.volume ?? 50   // 任一層不存在 → 50；volume 是 0 → 0

解法 C 補預設值到物件上：??=

options.retries ??= 3                         // 只在沒設定時寫入，0 次重試不會被蓋掉

補充 參數 / 解構預設值只看 undefined

function setVolume(v = 50) { return v }      // 預設值只在 v === undefined 時生效
setVolume(0)          // 0 ✓
setVolume(undefined)  // 50
setVolume(null)       // null —— 不會用預設值，要處理 null 時改用 v ?? 50

判斷 該用哪個

情境用
數字、布林、使用者輸入的字串，0 / false / "" 是合法值??
空字串也要顯示預設文字（例如空白的暱稱顯示「匿名」）||（這時 falsy 都要換掉是刻意的）
只想排除 undefined（函式參數沒傳）參數預設值 v = 50
不確定時用 || 給數字預設值不要

注意

  • ?? 不能直接和 || / && 混寫：a || b ?? c 是 SyntaxError，要加括號 (a || b) ?? c。
  • ?? 是 ES2020 語法，要支援很舊的瀏覽器需要經過 Babel / TypeScript 轉譯。
  • ?? 會保留 NaN：若 NaN 也要當成「沒有值」，要另外用 Number.isNaN() 判斷。
