TypeScript 常見錯誤：陣列先存成變數，就不再是 tuple

inline 傳 [10, 20] 沒事，先存成變數再傳就報錯 · 結論：在宣告變數時就標註型別（或用 satisfies），不要靠 as

原因

const pt = [10, 20] 沒有任何型別線索→TS 推論成 number[]→number[] 長度不固定→不能指派給 [number, number]
type Props = { point: [number, number] }        // 必須剛好兩個數字
const PointDisplay = ({ point }: Props) => <div>X: {point[0]}, Y: {point[1]}</div>

// inline：OK，TS 知道這個位置要 [number, number]，照著推論
<PointDisplay point={[10, 20]} />

// 先存變數：報錯
const pt = [10, 20]                              // 推論為 number[]
<PointDisplay point={pt} />
// Type 'number[]' is not assignable to type '[number, number]'.
//   Target requires 2 element(s) but source may have fewer.
  1. 直接寫在 props 位置時，TS 用上下文（這個 prop 要什麼型別）來推論 [10, 20]，所以得到 tuple。
  2. 先存成變數時，宣告那一行沒有上下文，TS 用預設規則推成最常用的 number[]。
  3. 型別在宣告時就決定了，之後傳給誰都不會再改；number[] 可能是 0 個或 100 個元素，不符合「剛好兩個」。
更正原筆記：
  1. 原筆記把 as [number, number] 列為解法之一。as 是型別斷言，意思是「相信我」，比標註弱：例如 nums as [number, number]（nums 是 number[]）可以編譯，但實際只有一個元素時 point[1] 就是 undefined。應優先用型別標註或 satisfies。
  2. 常見的另一個寫法 as const 得到的是 readonly [10, 20]，不能指派給可變的 [number, number]（錯誤：is 'readonly' and cannot be assigned to the mutable type）。要用 as const，props 型別要改成 readonly [number, number]。
  3. 原筆記結尾有多餘的程式碼區塊標記（```` 與未閉合的 ```），已移除。

名詞 先看懂這幾個詞

tuple（元組）
長度與每個位置型別都固定的陣列。[number, number] = 剛好兩個數字；number[] = 任意個數字。tuple 可以當成 number[] 用，反過來不行。
Contextual Typing（上下文型別推論）
TS 看「這個值要放到哪裡」來決定它的型別。例如寫在型別為 [number, number] 的 prop 上，[10, 20] 就被推成 tuple。離開那個位置（先存變數），上下文就沒了。
型別標註（annotation）
const pt: [number, number] = ...：宣告「這個變數必須是這個型別」，右邊的值會被檢查，少一個元素就報錯。
型別斷言（as）
value as T：告訴 TS「把它當成 T」，只要兩個型別有關聯就放行，不檢查實際內容。適合 TS 真的不知道、而你確定的情況，不適合拿來修推論問題。
satisfies（TS 4.9+）
expr satisfies T：檢查值是否符合 T，並以 T 作為上下文推論，但變數保留推論出來的精確型別。等於「給它上下文，又不放寬型別」。

解法 A 宣告時標註型別（首選）

直接把上下文補回來。

const pt: [number, number] = [10, 20]         // 宣告時就檢查：[10] 或 [10, 20, 30] 都會報錯
<PointDisplay point={pt} />                     // OK

// 不想重寫一次型別：直接引用元件的 props 型別，元件改了這裡也跟著變
const pt2: Props['point'] = [10, 20]

解法 B satisfies

想保留推論、又要檢查時用。

const pt = [10, 20] satisfies [number, number]   // 型別為 [number, number]，且內容經過檢查
<PointDisplay point={pt} />                     // OK

解法 C 要用 as const 時，props 接受 readonly

type Props = { point: readonly [number, number] }  // 元件本來就不該改 props，readonly 更貼切
const pt = [10, 20] as const                        // readonly [10, 20]
<PointDisplay point={pt} />                         // OK；一般的 [number, number] 也仍可傳入

判斷 該用哪個

情境用
一般變數型別標註（可引用 Props['point']）
要檢查，又想保留更精確的推論（例如設定物件）satisfies
常數資料、不會被修改as const + props 用 readonly
為了消除錯誤而寫 as [number, number]不要，會把真正的錯一起藏掉

注意

  • satisfies 需要 TypeScript 4.9 以上；舊版本只能用標註。
  • tuple 只在型別層保護長度：pt.push(30) 在可變 tuple 上仍然能編譯，要真正防止修改請用 readonly。
